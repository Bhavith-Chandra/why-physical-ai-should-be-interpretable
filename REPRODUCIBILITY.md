# Reproducibility concept

This repository follows one rule: **no number in the paper is typed by hand.** Every value printed in the PDF is a LaTeX macro in `numbers.tex`, and that file is generated by `code/aggregate.py` from the per-seed result files in `code/results/`. Reproducing the paper means re-running the pipeline and checking that the same file comes out.

The concept has five layers. Each one guards against a different way an ML result can be wrong.

## 1. Determinism: the same command gives the same bytes

| Source of randomness | How it is controlled |
|---|---|
| Data generation | `numpy.random.default_rng(seed)`, with disjoint streams per run: `base = 1000*seed + (0 or 500)`, then `+1` train, `+2` val, `+3` decorrelated, `+4` OOD-g, `+5` OOD-damping |
| Weight init and batch order | `torch.manual_seed(seed)` before model construction and training |
| Threading | `torch.set_num_threads(2)`, CPU only, so there are no non-deterministic GPU kernels |
| Library drift | exact versions pinned in `requirements.txt` |

**Check D1** retrains `confounded` seed 0 from scratch into `code/rerun/` and requires every stored metric to match to within 1e-6.

*Scope:* bit-identical reproduction is guaranteed only on the same library versions and CPU architecture. On other hardware, expect small numerical differences. The claims are stated as *inequalities that must hold in every seed* (layer 3) precisely so that they survive such differences.

## 2. Provenance: every number has a single path to the paper

```
simulate() ──► run.py ──► results/<mode>_s<seed>.json ─┐
                      └─► results/<mode>_s<seed>.pt ───┼─► posthoc.py ─► results/posthoc.json ─┐
                                                       └─► triangulate.py ─► results/triangulation.json
results/*.json ──────────────────────────────────────────────► aggregate.py ─► numbers.tex + figures
                                                                      validate.py ─► VALIDATION.md
```

**Check P1** regenerates `numbers.tex` from the committed results and requires it to be identical to the committed file. If someone edits a number by hand, or a result file changes without the paper being rebuilt, P1 fails.

## 3. Validation: claims are executable

Each sentence in the paper that makes an empirical claim corresponds to a check in `code/validate.py`. A claim passes only if it holds **in every seed**, not on average. For example:

- C1: the confounded model has lower validation error than the causal model (so validation selects the shortcut).
- C4: the do(colour) intervention shifts the confounded model's predictions more than 5× as much as the causal model's.
- C9: pre-action monitors stay below 0.65 AUROC (the negative result is also a checked claim).

`make validate` writes `VALIDATION.md` and exits non-zero if any claim fails.

## 4. Triangulation: every headline claim is confirmed by an independent method

A result that depends on a single measurement choice is fragile. `code/triangulate.py` re-derives each headline claim a second way:

| Claim | Primary method (paper) | Independent method |
|---|---|---|
| Error ordering | intensity-centroid angle readout | **T1** argmax-pixel readout |
| Causal model "does not know g" | linear probe R² ≈ 0 | **T2** matches a simulator oracle that knows the state but uses mean g; **T3** nonlinear probes (MLP, kNN) |
| Confounded model "reads g from colour" | probe geometry, colour flip | **T2b** matches a simulator oracle with g = 6 + 8·redness; **T4** graded dose-response |
| Gaps are not noise | seed mean ± s.d. | **T5** episode-level bootstrap 95% CIs, per seed |
| Why gravity is hard to infer | (none) | **T3b** perfect-sensor control: exact angles identify g (R² > 0.99), pixel readouts do not |

The oracles in T2 are physics simulations, not learned models. They provide ground-truth reference points that no training choice can influence.

## 5. Honest reporting

- Negative results (latent steering does not reproduce the shortcut; pre-action monitors near chance) are reported in the paper and enforced as claims C8 and C9, so they cannot quietly disappear in a later revision.
- Bugs found during validation are recorded in `CHANGELOG.md`. Validation found one: an earlier draft stated that the angle readout is exact to 1e-6 rad, but after a threshold was added to the readout its true error is a few milliradians. The paper now reports the measured value.

## Commands

```bash
pip install -r requirements.txt
make all        # train 5 seeds x 2 conditions, post-hoc, triangulate, aggregate, validate, build PDF (~60 min, 2 CPU cores)
make validate   # only re-check claims against committed results (~3 min)
make smoke      # 1-minute end-to-end pipeline test (what CI runs)
```
